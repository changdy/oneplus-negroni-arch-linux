## 显示模式与节拍

DRM 与 SDDM 的 KWin 都列出 1080×2412 和 1440×3216 各 60 / 90 / 120 Hz。切换时从 KMS 读取活动 CRTC 94，并在 `DRM_IOCTL_MODE_CRTC_QUEUE_SEQUENCE` 持有 vblank 引用期间采样。单纯读取两次计数会受中断空闲屏蔽影响，未作为节拍依据。

| 熄屏前活动模式 | 实测 vblank |
| --- | --- |
| 1080×2412 @ 120 Hz（启动首选） | 120.10–120.18 Hz |
| 1440×3216 @ 60 Hz | 59.95–60.71 Hz |
| 1440×3216 @ 90 Hz | 空闲 60.76–61.44 Hz，FD730 渲染期间一次 80.16 Hz |
| 1440×3216 @ 120 Hz | 120.04 Hz |

90 Hz 模式可提交到 CRTC，固定 90 Hz 节拍未验证。原厂 90 Hz 条目有 ADFR 配置，Linux 中节拍变化的原因待查。

## 熄屏与恢复

1440×3216 @ 120 Hz 熄屏 2 秒后，DRM 恢复为 On，但 DPU 的 TE 读指针中断计数停在 4797。随后六档模式均能提交到 CRTC，观察时 TE 计数不再增长。切回 1080×2412 @ 120 Hz，恢复原 2.6 倍缩放，并重启未登录的 SDDM greeter 后，TE 中断仍未恢复。后来登录界面在 FHD+ 下自动熄屏，重新点亮后也无新增 TE 中断。

恢复后 DRM 确认 1080×2412 @ 120 Hz 活动，FD730 可渲染，DPU 帧传输完成中断从 1612 增至 2949，面板的 DCS 亮度读回为 400。08:17–08:21 的模式切换及熄屏测试未记录新的 DSI、DPU 或 GPU 超时。08:22:29 后续读取状态时另有一次 `dsi_err_worker: status=5`，与 TE 停止的关系待查。

用户确认切回 1080×2412 后登录界面显示正常。10:08 USB SSH 确认桌面已在 **1440×3216 @ 120 Hz**，用户随后确认画面显示和更新正常。此时 TE 计数仍为 4797，DPU 帧传输完成中断已增至 9223。熄屏后的 TE 恢复与实际扫描节拍仍待验收。原始输出保存在忽略目录 `logs/display-native-20261118/`。

同日已定位并修复熄屏后 TE 中断丢失。内核 `#10` 的六轮唤醒结果见[后续实测](../display-te-20261118/README.md)。
