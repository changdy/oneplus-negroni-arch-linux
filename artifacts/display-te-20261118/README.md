# NE2210 熄屏后显示同步中断恢复（2026-11-18）

## 定位

在内核 `#9` 的 1440×3216 @ 120 Hz 模式下，GPIO86 在 150 ms 采样中有 18 个 TE 上升沿，DPU 的硬件帧计数也增加 18。DPU 的 TE 中断状态有挂起位，硬件使能寄存器为 `0x0`，而驱动在锁内读取到的缓存为 `0x4`，回调已注册。临时诊断模块按驱动缓存写回 `0x4`，Linux 中断计数立即从 4797 增长。模块随即卸载。

同一内核、同一显示模式分别熄屏 2 秒。DPU 临时设为 `on` 时，亮屏后使能仍为 `0x4`，中断继续增长。恢复 `auto` 后，DPU 在熄屏时达到 `suspended`，亮屏后硬件使能再次为 `0x0`，缓存仍为 `0x4`。对照结束恢复 `auto`，再次按缓存写回后中断恢复。

## 修复与实测

内核提交 `3d1c9125328c` 在 DPU 恢复时，完成时钟和编码器恢复，再持 IRQ 锁将所有受支持的中断组恢复到缓存的使能掩码。回调注册和运行时省电沿用原路径。ARM64 内核和模块构建通过，`Module.symvers` 与原配置一致。

经用户同意，只刷写 `boot_b` 并重启一次。内核 `#10` 已启动，B 槽 Active / Successful / Bootable 均为 1。核对了完整备份和刷后读回的 SHA-256。
