# 相机预览偏色核查（2026-11-13）

本次为离线分析，未连接或启动相机，沿用 `logs/camera-20261113/` 中的 `real-exposed.raw` 和 `bars-newboot.raw`。原始图像及处理预览留在 `logs/camera-colour-20261113/`，不随 Git 提交。

结论：上一轮预览缺少白平衡和模组颜色矩阵。相同 RAW 和显示曝光下，加入估计白平衡后整体偏绿明显改善，主要原因指向预览处理缺失。当前没有受控中性参考或色卡，不能把该结果视为完成颜色标定。

## 数值依据

- RAW：4080×3072、GRBG10 / `pgAA`，stride 5104；每行前 5100 字节为有效 RAW10。
- 色条：按顺序读取预览中心得到 `[255,255,255]`、`[255,255,0]`、`[0,255,255]`、`[0,255,0]`、`[255,0,255]`、`[255,0,0]`、`[0,0,255]`、`[0,0,0]`，与预期完全相同。结合代码与格式规范核对，未发现打包格式或 GRBG 相位错误。
- 实拍帧：`real-exposed.raw` 的第 3 帧；假设黑电平 64，选择完整 RAW 坐标 `(240,1560,360,200)` 的梁面区域。剔除近黑及高亮单元后，RGB 中位数为 `66 / 112 / 78`。
- 估计白平衡：`112/66, 1, 112/78` = `1.6969697 / 1 / 1.4358974`。这依赖“所选梁面为中性”的假设，未证明其实际反射率。
- 其他两个疑似中性区域估计约为 `1.82 / 1 / 1.67`、`1.65 / 1 / 1.47`，不应把单一区域增益当成跨场景常数。
- 同一帧中两种绿色相位的差值中位数为 0；原预览已经平均两种绿色，并非把两种绿色直接相加。

对比使用同一黑电平、RAW 白点 1023、曝光 EV=0、sRGB 传递函数和缩放方式，只改变白平衡增益。新工具没有颜色矩阵、镜头阴影或色卡标定，相关项目仍未完成。

## 复现

使用 [negroni-camera-raw-preview.py](../../scripts/negroni-camera-raw-preview.py)，依赖 NumPy、Pillow；具体命令和适用范围见[相机说明](../../docs/camera.md)。输出 PNG 旁保存 JSON 元数据，含帧号、黑电平假设、增益、ROI、显示传递函数和未实现的处理步骤。

格式来源：[Linux packed RAW10 文档](https://docs.kernel.org/userspace-api/media/v4l/pixfmt-srggb10p.html)。处理流程依据：[libcamera Camera Model](https://docs.libcamera.org/master/public-api/camera-model.html)。
