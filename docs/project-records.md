# 项目成果与对话整理规范

整理日期：2026-11-15。本轮覆盖当前工作区的 23 个既有 Codex 对话、36 个 Cursor 对话，其中归档分别为 3 个和 22 个；同时核对 3 份相关历史研究子任务。Cursor 有 9 个记录仅包含模型错误或停止标记，另有一个问候对话，均在清单中明确处理，没有伪造技术结论。压缩记录有历史部分的也纳入核对。逐个记录的标题、ID、归档状态、主题文档和处理结果见[对话核对清单](../artifacts/project-audit-20261115/conversations.json)。这是整理后的索引，不含原始聊天、命令输出或凭据。

## 交付标准

- 已验证能力要同时保留内核提交及其 gitlink/bundle、用户空间代码和必要依赖、首次安装与续建更新、打包缺件检查。中文字体、登录键盘、SSH、自动扩容、桌面配置与应用集成同样适用。
- 已验证可用、没有明显稳定性或耗电影响的驱动默认启用；按需访问的设备不需要开机持续工作。存在已知问题或证据不足时，保留可直接调用的入口，并写清待验证项。现有 GPU runtime PM 规避和 CPU performance 策略的功耗取舍继续在各自文档中说明，不能据此宣称已经完成省电验证。
- 只完成底层时，把这一层交付。四摄 RAW、NFC UID、GNSS 引擎启动分别不能等同完整相机、门禁模拟、定位导航。
- 基础应用默认安装；串流及专门调试工具提供按需安装方法，见[可选应用](optional-apps.md)。
- 有价值的失败实验保留代码、补丁、适用版本、操作步骤、结果、恢复方法和下一步；默认构建不执行失败实验。区分失败、未完成、未测和无法判断。
- 同一个硬件以一个主要文档为当前入口。使用方法和结论放前面，根因与历史放后面或链接到 `docs/archive/`、`artifacts/`。历史证据按日期解释，已被后续结果替代的结论明确标注。
- 凭据、私钥、分区镜像、设备校准、私人照片及原始日志不入 Git。原厂模块只沿已有精确例外归档；原厂固件与校准继续使用本机加载或来源明确的现有软件包。

## 状态和验收

相机已列为持续专项。当前进度、试验优先级、分镜头验收条件和本地讨论来源统一维护在[相机优化与修复专项](camera.md#相机优化与修复专项)。

每项分别记录：源码是否齐全、实机验证了哪种能力、打包是否接通、新镜像是否实际验证。资料之间矛盾时，结合提交和较晚实测核对，不能直接采用聊天末尾的一句“完成”。

本轮验收为源码、配置、安装/续建路径和离线检查。检查方法：

```sh
bash scripts/check.sh
sudo bash scripts/check-image-delivery.sh
git diff --check
```

第二组用小型 ext4 夹具检查真实安装器和打包校验器，覆盖缺文件、错误权限、旧源码、同 release 不同 ABI、服务未启用等拒绝情况。它不运行手机硬件，也不代表完整镜像已经构建、刷入或通过冷启动/耗电验证。相机额外模块另用当前固定内核输出交叉编译核对。

后续优先验证新完整镜像的冷启动和日常使用，再补另外三摄开机/休眠/空闲功耗、传感器新文件目录启动、GNSS 室外定位、蓝牙配对/A2DP、USB Hub/深睡和长期负载。刷分区、重启和推送仍按 [AGENTS.md](../AGENTS.md) 要求另行确认。
